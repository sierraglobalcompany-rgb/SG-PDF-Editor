## Delivered user-facing product scope

### Text watermark

`Herramientas` exposes `Marca de agua de texto...` with focused settings for text, all/current/explicit page scope, 9 anchors, font size, opacity, rotation, foreground/background layer and RGB color.

Persistence delegates to the transactional F9 text-overlay writer. Unsupported glyphs fail closed under the pinned DejaVu Sans 2.37 policy. Source PDFs are not modified in place.

### Page numbering / Bates

`Herramientas` exposes `Numerar páginas / Bates...` with starting number, prefix/suffix, zero padding, all/current/explicit range, six header/footer anchors, font size, opacity, foreground/background layer and RGB color.

One formatter/planner path covers both ordinary numbering and Bates-style numbering.

### Authorized password protection

`Herramientas` exposes `Proteger con contraseña...`.

Exact pinned PDFium `156.0.8076` was proven unable to create encryption through its public API. Exactly one local fallback was therefore selected: qpdf 12.4.2.

Product behavior:

- creates a new AES-256 open-password protected copy;
- explicit user authorization is required;
- current source password must be supplied again for a source opened with a password;
- no password bypass/removal exists;
- cryptographically signed sources fail closed;
- user/owner passwords travel only through ephemeral qpdf job JSON, not process arguments;
- output is created through sibling temp → reopen/validate → atomic publication → cleanup;
- original source remains unchanged.

Print/copy/edit permission toggles are intentionally not exposed because F9 did not prove a sufficient cross-reader enforcement matrix and does not market those flags as DRM.

## Capability decisions intentionally left unexposed

No rasterization, downsampling, JPEG conversion or destructive image recompression is used. Output is not required to be smaller.

That small synthetic corpus is insufficient to promise generic repair, so no placebo Repair UI exists.
