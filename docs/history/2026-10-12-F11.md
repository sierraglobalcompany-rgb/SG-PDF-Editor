## Resultado

F11 implementa la capa Texto V2 aprobada sin convertir SG PDF Editor en un procesador Word-like.

Flujo final:

```text
PDFium text objects + geometry
→ TextLayoutAnalyzer
→ TextLayoutPage / columns / paragraphs / lines / runs
→ TextReflowPolicy
→ TextReflowPlanner
→ TextEditWorkspace.ApplyReflowPlan
→ PdfEditWriter existente de Texto V1
→ Save As + reopen/validate
```

## Entregado

- Reading order geométrico y determinista, independiente del orden bruto de objetos PDF.
- Líneas y párrafos reconstruidos de forma conservadora.
- Detección de una/dos columnas simples; geometría inestable se marca `Ambiguous`.
- Texto rotado/incompatible se marca `Unsupported`.
- Integración real con PDFium y corpus OCR F10.
- Gate PdfPig concluido como **NO-NEED**: PDFium aportó datos suficientes para el alcance aprobado.
- Política explícita de reflow seguro: una columna, `Simple`, estilo homogéneo, sin solapes, render mode editable y preflight general permitido.
- Planner conservador que reutiliza objetos de texto existentes; no crea layout libre ni reposiciona objetos.
- Aplicación atómica al workspace de Texto V1; ningún cambio parcial si una asignación no supera su política.
- Reutilización del writer transaccional existente; no existe un segundo writer F11.
- UI WPF mínima dentro de EDITAR: párrafo reconocido, estado seguro/no seguro, motivo español y botón `Aplicar reflow seguro`.
- Análisis page-scoped y bajo demanda al seleccionar texto; F11 no preanaliza todo el documento.

## Preservación

F11 no altera la propiedad del PDF ni introduce una ruta paralela de escritura. La matriz específica está en `docs/history/2026-10-12-F11-preservation-matrix.md`.

Puntos principales:
- source intacto por Save As;
- edición avanzada bloqueada antes de mutar cuando el layout no es seguro;
- `ApplyReflowPlan` prepara todos los candidatos antes de hacer commits al workspace;
- el writer existente reabre/valida el resultado;
- Task 5 añadió evidencia de salida renderizada;
- OCR F10 permanece explícitamente de solo lectura para reflow cuando usa render mode invisible.

## Fuera de alcance preservado

No se añadió:
- reflow libre de página completa;
- editor Word-like;
- tablas complejas;
- texto vertical editable como flujo;
- layouts arbitrarios/flotantes;
- inferencia semántica agresiva;
- PdfPig u otro motor PDF.

## QA todavía abierta

**NOT RUN:**
- uso real de la UI de reflow en Windows;
- PDFs privados/representativos;
- layouts editoriales complejos reales;
- Adobe Acrobat/Foxit/Edge sobre salidas F11;
- prueba física offline en equipos representativos.

Por tanto, F11 puede cerrarse **automatizadamente** después del exact-head CI del commit documental, pero no debe describirse como producción/manual totalmente certificada.
