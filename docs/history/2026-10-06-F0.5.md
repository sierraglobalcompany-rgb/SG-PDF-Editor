## Objetivo

Implementar `PDF-BASE-06`: impresión de PDFs mediante Windows, incluyendo el flujo estándar hacia Microsoft Print to PDF.

## Contexto heredado

F0.1–F0.4 ya estaban automatizadamente verdes:

- apertura/render PDFium;
- navegación;
- zoom/fit;
- scheduler latest-request-wins + cancelación cooperativa.

F0.5 debía añadir impresión sin romper el enfoque KISS ni introducir una librería de impresión adicional.

## Decisión técnica

Se validó contra documentación Microsoft que WPF dispone de `System.Windows.Controls.PrintDialog`, soporta selección de impresora, página actual/rango y envío de un `DocumentPaginator` mediante `PrintDocument`.

Por tanto se eligió:

`PDFium -> PdfDocumentPaginator -> WPF PrintDialog -> Windows spooler/printer`

No se creó ruta especial para Microsoft Print to PDF: si está instalada, aparece como cualquier otra impresora Windows.

## Implementación core

### `PdfPrintRange`

Añadido en `src/SGPdf.App/Printing/PdfPrintRange.cs`.

Soporta:

- `All(pageCount)`;
- `Current(currentPageIndex, pageCount)`;
- `UserPages(firstPageNumber, lastPageNumber, pageCount)`.

La API interna conserva índices 0-based y convierte explícitamente los números 1-based del diálogo de Windows.

### `PdfDocumentPaginator`

Añadido en `src/SGPdf.App/Printing/PdfDocumentPaginator.cs`.

Comportamiento:

- implementa `DocumentPaginator`;
- produce páginas bajo demanda;
- usa la sesión PDFium existente;
- renderiza a 200 DPI;
- crea `BitmapSource` BGRA;
- ajusta proporcionalmente al área imprimible;
- centra el contenido;
- devuelve `DocumentPage` al pipeline WPF.

No mantiene un cache completo del documento ni crea archivos temporales.

## Integración UI

`MainWindow` incorpora `Archivo > Imprimir...`.

El comando:

1. solo se habilita cuando hay PDF abierto y la app no está ocupada;
2. cancela un auto-refit pendiente;
3. abre `PrintDialog` de WPF;
4. habilita página actual y rango continuo;
5. fija límites 1..PageCount;
6. convierte la selección a `PdfPrintRange`;
7. construye `PdfDocumentPaginator` con `PrintableAreaWidth/Height`;
8. envía con `PrintDocument`;
9. muestra error controlado si falla el driver/spooler.

No se agregó atajo `Ctrl+P` falso ni texto decorativo sin comportamiento real.

## Riesgos/decisiones conscientes

### Raster de impresión

La salida F0.5 es rasterizada por PDFium a 200 DPI antes de entrar al pipeline WPF. Esto simplifica mucho la implementación y reutiliza el motor ya validado.

Trade-off:

- suficiente para validar la función base;
- puede no ser el nivel final de calidad/memoria para todos los PDFs.

F0.6 debe medir PDFs reales y decidir si conviene ajustar DPI o introducir una estrategia diferente. No se optimiza preventivamente.

### Orientación

F0.5 respeta el área imprimible reportada por la impresora y ajusta el contenido preservando proporciones. No cambia automáticamente portrait/landscape: esa elección queda al driver/usuario en el diálogo estándar.
