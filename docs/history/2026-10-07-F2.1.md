# F2.1 — ZPL Parse + Open — Historial

**Fecha:** 2026-10-07  
**Rama:** `feat/f2-1-zpl-parse-open`  
**PR:** #13 draft, base `design/f2-labelize-architecture`, sin merge

## Objetivo

Crear la primera slice productiva de etiquetas ZPL sin introducir todavía el renderer externo: abrir `.zpl/.txt/.prn` locales, detectar diseños imprimibles, conservar `^PQ` como cantidad separada, preservar contexto `^DF/^XF` y cambiar de workspace solo después de una carga válida.

## Contexto arquitectónico

El Gate ZPL-A sintético se ejecutó previamente en `spike/f1-zpl-gate-a` y seleccionó **Labelize 1.7.0** como motor F2. La integración aprobada para F2.2 es un `labelize.exe` local pinneado ejecutado como child process; BinaryKits no queda como fallback runtime.

F1 no se considera formalmente cerrado hasta ejecutar el corpus privado real de Mercado Libre. Los archivos privados nunca se versionan.

## Implementación F2.1

### Modelo y parser

Se añadieron:

- `Features/Labels/ZplDesign.cs`;
- `Features/Labels/ZplDocument.cs`;
- `Features/Labels/ZplDocumentParser.cs`.

Comportamiento:

- descubre bloques completos `^XA...^XZ` en orden;
- rechaza `^XZ` suelto, `^XA` sin cierre y `^XA` anidado;
- `^DF` es bloque de soporte, no diseño visible;
- `^XF` permanece en el stream document-level;
- `NormalizedRenderSource` preserva el contexto necesario para el renderer posterior.

### Cantidades `^PQ`

- ausencia => 1;
- `^PQ0` => 1;
- último `^PQ` del bloque imprimible gana;
- máximo aceptado 99,999,999;
- malformed/out-of-range => `InvalidDataException`;
- todos los `^PQ` se eliminan del render source;
- no se duplican bloques ni renders;
- `QuantityFromFile` es `int`;
- `TotalQuantityFromFile` es `long`;
- `^PQ` dentro de `^DF` se rechaza en F2.1 para no inventar semántica de stored formats.

### Loader local

`ZplFileLoader`:

- acepta `.zpl`, `.txt`, `.prn` case-insensitive;
- resuelve path local;
- UTF-8 estricto;
- acepta BOM UTF-8;
- no adivina otras codificaciones;
- no hace red, temp copy ni proceso externo;
- delega parsing al parser managed.

### WPF

Se añadió `Archivo > Abrir etiquetas ZPL...` y `MainWindow.Labels.cs` como partial de la misma ventana.

La decisión de usar partial evita seguir inflando `MainWindow.xaml.cs` sin crear ViewModel, mode service ni capas nuevas.

Flujo:

1. diálogo local;
2. `Task.Run(() => ZplFileLoader.Load(...))`;
3. no se toca el workspace actual durante candidate load;
4. éxito: se cancela refit pendiente, se libera PDF previo, se activa `_zplDocument`, se oculta viewer PDF y se muestra placeholder con diseños/cantidad;
5. fallo: error controlado y el documento previo permanece activo;
6. cuando un PDF válido vuelve a mostrarse, la referencia ZPL previa se limpia;
7. ambos comandos de abrir respetan el busy state existente.

No se añadió Labelize, BinaryKits, PDFsharp, ZXing ni otro paquete.
