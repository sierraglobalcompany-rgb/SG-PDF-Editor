## Scope

F5 adds page-level structural organization to SG PDF Editor without turning the application into a generic PDF object-tree editor. The feature is plan-first and local-only: the user edits an in-memory page-reference plan and materializes a validated copy through `Guardar como...`.

Implemented operations:

- reorder/move one or many pages;
- rotate in 90° increments;
- delete and duplicate;
- insert selected ranges from another PDF;
- merge/append another PDF through the same insert path;
- extract selected pages;
- split every N pages or by explicit ranges.

Frozen exclusions remained intact: no image/text editing, comments, OCR, cryptographic signing, generic repair, second PDF engine, cloud/account/API key/network runtime, preventive architecture layer or source overwrite.

## Architecture retained

- Windows x64, C#/.NET 10, WPF.
- PDFium remains the only PDF engine.
- `PdfiumRuntime.NativeGate` remains the global `SemaphoreSlim` serialization boundary.
- Labelize 1.7.0 remains the only runtime ZPL renderer.
- PDFsharp remains labels/synthetic-fixture support, not the F5 editor engine.
- FIRMAR remains based on the existing `SignatureAsset` path.
- Structural output is Save As only.

## Task history

### Task 0 — NativeGate prerequisite

F4 Navigation used `lock (PdfiumRuntime.NativeGate)` even though `NativeGate` is a `SemaphoreSlim`. Task 0 moved bookmarks/links to `Wait/Release` and removed a nested-gate deadlock by reading page count directly while the gate is held. This was an F5 prerequisite, not a feature expansion.

### Task 1 — PDFium capability gate

The exact pinned DLL proved the critical APIs required for the chosen writer route: new document creation, exact page import, page rotation read/write and SaveAsCopy. A protected-session marker records only whether a non-empty password was supplied successfully; the password itself is never retained.

### Task 2 — Plan model

Added immutable source/page references and pure operations. Source fingerprints use file length + last-write UTC ticks. Move semantics preserve current visual order; rotation composes modulo four; delete-all is blocked; duplicates get new logical IDs; inserted sources remain explicit.

### Task 3 — Structural preflight

Added small `Info | Warning | Block` findings and `ProvenPreserved | ProvenChangedOrLost | Unknown` preservation status. Signatures and password-opened PDFs are hard blocks. Detectors use existing F4 navigation where possible plus narrow PDFium probes.

### Task 4 — Writer + validator

Materialization follows the frozen transactional path:

```text
validate plan/fingerprints/preflight
→ create temp destination
→ open source sessions without stored credentials
→ import exact pages in final order
→ apply relative rotation
→ save temp
→ close native handles
→ reopen temp
→ validate exact page count/size/rotation
→ render every output page sequentially at 36 DPI
→ atomically publish
→ cleanup temp best-effort
```

Existing destination contents are preserved on stale source, native failure, validation failure or blocked preflight.

### Task 5 — ORGANIZAR surface + thumbnails

Added a dedicated virtualized organize surface. Thumbnails are lazy and bounded to realized items plus a small neighbor window. Stale publication is rejected; one tile failure is isolated; reorder reuses bitmap state.

### Task 6 — Selection, drag/reorder and Save As

Implemented familiar Windows selection semantics: click, Ctrl+click, Shift+click, Ctrl+A, Escape and Delete. Multi-selected drag moves one ordered block. Save As aggregates preflight and requires warning confirmation where applicable; success reports the saved path without silently replacing the active reader session.

### Task 7 — Insert + merge

Secondary PDFs are candidate-first. Password-required secondary sources are rejected. One-based range input is parsed to validated zero-based unique page indices. Merge reuses insert-all append behavior instead of adding another engine.

### Task 8 — Extract + split

Extraction materializes a derived plan without mutating the workspace. Split supports every-N and explicit non-overlapping ranges. Output names are deterministic. Batch publication checks every collision before the first write, then stops on the first failure while retaining already-published earlier outputs.

### Task 9 — preservation hardening

Representative synthetic fixtures were passed through the **real F5 writer** and reopened. Evidence showed that identity page import does not preserve the following source structures with the current writer:

- forms;
- bookmarks;
- internal links;
- named destinations;
- tagged structure;
- page labels;
- attachments;
- original metadata values such as Title/Author.

Those findings were upgraded from `Unknown` to `ProvenChangedOrLost` and remain Warning + explicit confirmation. Cryptographic signatures and password-opened sources remain Block with no override. See `docs/history/2026-10-09-F5-preservation-matrix.md`.

### Task 10 — closure hardening

A real remaining gap was found: leaving ORGANIZAR or opening another PDF could silently discard an unsaved plan. TDD added a narrow dirty guard:

- mutating the plan sets dirty;
- successful Save As clears dirty;
- opening another PDF asks before discarding;
- switching to LEER/FIRMAR or ZPL asks before discarding;
- cancel preserves the current session/plan;
- materialization blocks mode-leave mutation.
