## Scope

F6 adds local editing of real PDF image page objects without converting pages into screenshots and without introducing a second PDF engine.

Implemented behavior:

- detect/select real image page objects on the active PDF page;
- deterministic hit-testing for rotated/overlapping images;
- visually faithful PNG extraction;
- PNG/JPEG replacement while preserving current geometry;
- move, resize, rotate and delete;
- opacity 0–100%;
- z-order forward/back/front/back;
- undo/redo;
- dirty-state protection;
- transactional Save As with source fingerprint, reopen/render validation and atomic publication.

Explicit exclusions remain: image crop, image multi-select, cross-PDF image copy/paste, generic page-object editing, vector editing, text editing, OCR, comments, cryptographic signing, page flattening and raster-overlay fallbacks.

## Architecture retained

- Windows x64, C#/.NET 10, WPF.
- PDFium remains the F6 PDF engine.
- `PdfiumRuntime.NativeGate` remains the global native serialization boundary.
- No durable PDFium `IntPtr` is stored in image workspace state.
- UI works on immutable/logical managed state; native objects are resolved fresh only during bounded operations.
- Save As reopens the unchanged original source and materializes the complete logical image state.
- Existing destination is replaced only after temporary output successfully reopens and validates.
- Labelize remains ZPL-only; PDFsharp remains labels/synthetic-fixture support.

## Task history

### Task 1 — exact capability gate + image discovery

The exact pinned PDFium runtime was probed for the required page-object/image APIs. Core discovery/extraction/matrix/remove/generate/save routes passed. Optional routes required by opacity, exact-index insertion, rotated bounds and rendered object bitmap were characterized against the packaged DLL rather than assumed from upstream documentation.

Image discovery returns managed snapshots only and closes native page/bitmap handles before returning.

### Task 2 — logical workspace/history

Added source fingerprinting, stable logical object keys, current image state, complete edited-state rematerialization and command history. Successful Save As can establish a saved logical baseline without reopening the destination as the active source.

### Task 3 — EDITAR surface + hit-testing

Added the EDITAR image surface with one active selection, WPF overlay and deterministic PDF-space hit-testing. Only the active page is enumerated. Signed/password-opened sources are blocked before a mutable image workspace is created.

### Task 4 — transforms/delete + undo/redo + dirty guard

Added move, proportional/free resize, rotate-around-center, logical delete, gesture commit semantics, Ctrl+Z/Ctrl+Y and dirty guards for mode leave/open/close.

### Task 5 — extract + replace

Added visually faithful PNG extraction and candidate-first PNG/JPEG replacement. Replacement content is captured into managed memory at selection time, so later save does not depend on the external source file still existing.

Transparent PNG replacement is covered by save/reopen/render evidence; no white-flatten fallback is used.

### Task 6 — transactional writer

`PdfImageEditWriter` reopens the original source, verifies fingerprint/signature/password policy, resolves all edited original objects on each touched page before mutations that can shift indices, applies replacement/matrix/delete operations, regenerates touched page content, saves to a same-directory temp, reopens and validates the output, then atomically publishes.

Failure, cancellation, stale source, native save error and validation error preserve the source and prior destination and clean temporary output best-effort.

### Task 7 — opacity + z-order

Both optional exact-runtime gates passed.

Opacity uses the proven PDFium fill-alpha route and supports 0–100% with deterministic rounding and undo/redo. Z-order uses the proven remove + exact-index reinsertion route and works relative to image and non-image neighbors without duplication/loss.

Therefore IMG-03 is not partial: move/resize/rotate/delete + opacity + z-order all have automated evidence.

### Task 8 — independent preservation matrix + Save As policy

F6 built its own preservation matrix instead of inheriting F5's page-import losses.

Representative real-writer fixtures with a minimal image edit prove preservation of:

- forms;
- bookmarks;
- named destinations;
- internal links;
- tagged structure;
- page labels;
- attachments;
- representative metadata values.

These are `ProvenPreserved / Info` for the tested F6 route. Cryptographic signatures and password-opened sources remain `Unknown / Block` because F6 refuses to materialize them. See `docs/history/2026-10-09-F6-preservation-matrix.md`.

The Save As UI invokes the writer only after preflight permits output; warnings require one explicit confirmation; Block/decline invokes the writer zero times. `MarkSavedBaseline()` occurs only after success.

### Task 9 — hardening/regressions/memory ownership

RED exposed three real gaps: Ctrl+O dirty handling, Abrir ZPL dirty handling and unbounded managed bitmap copy. GREEN added early open guards plus bitmap format/stride/size validation and a 256 MiB combined source+BGRA managed-copy budget before allocation.

Additional tests prove:

- cancellation after validation and publication failure preserve prior valid output and clean temp;
- EDITAR discovers only the active page on entry;
- image workspace/state/assets do not persist `IntPtr`/`UIntPtr` native handles;
- replacement save uses captured bytes after the external replacement file is deleted.
