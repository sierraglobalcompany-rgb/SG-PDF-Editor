## Goal

Add a small reusable local signature library without creating a second PDF/signature engine. Every source and reused signature still converges to the existing contract:

```text
SignatureAsset → AddSignatureAsset(...) → existing placement/save flow
```

The library persists only transparent signature assets under `%LOCALAPPDATA%\SG PDF Editor\Signatures\`; PDF placement/page/dirty state is never persisted by the library.

## Delivered

### Storage and manifest

- `library.json` v1 plus local PNG files.
- Missing root/manifest loads as an empty library without eager creation.
- Corrupt/unsupported manifest becomes controlled unavailable state and is never auto-repaired.
- Stable unique GUID metadata, safe simple PNG paths and manifest order preservation.
- User-facing names are trimmed/validated on Add/Rename; duplicates use `OrdinalIgnoreCase`.

### PNG persistence and mutations

- `SignatureAsset` BGRA → WPF `BitmapSource` → `PngBitmapEncoder`.
- Alpha and dimensions are preserved without intentional resizing/reprocessing.
- Existing `SignaturePngLoader` remains authority on reload, including transparency and 20M decoded-pixel guard.
- Add ordering: validate → temp PNG → publish PNG → publish complete manifest.
- Manifest writes use same-directory temp + replace/move; never truncate `library.json` in place.
- Failed Add rolls back only the PNG created by that operation best-effort; cleanup failure leaves a harmless ignored orphan.
- Rename is manifest-only.
- Delete publishes metadata removal first, then deletes PNG best-effort; cleanup failure does not resurrect the item.

### Library UI

- `Biblioteca de firmas...` dialog with thumbnail, visible name and unavailable state.
- Actions: Use, Save selected, Rename, Delete, Close.
- Missing/corrupt PNG stays isolated to its own row; healthy items remain usable.
- Corrupt manifest disables unsafe mutation/use while Close remains available.
- Name and delete confirmation seams stay local to the dialog; no global framework/DI was introduced.

### FIRMAR integration

- Added `Biblioteca de firmas...` to the existing code-built FIRMAR properties panel.
- The dialog receives the exact selected placement's `SignatureAsset`, or null when none is selected.
- Cancel/null/failure causes no signature-state mutation.
- Successful Use calls the existing `AddSignatureAsset(asset)` exactly once.
- F3.1 remains authority for centering, geometry, selection, dirty state, overlay and Save As.

Implementation adaptations discovered during TDD:

- `SignatureLibraryUnavailableException` inherits `IOException` because .NET 10 seals `InvalidDataException`.
- `SignatureLibraryFileOps` delegate properties are internal `set` rather than `init` so deterministic failure tests can replace the default direct-I/O delegates; no public/runtime service surface was added.
