# History — 2026-10-08 — F3.1 Visual Signature Core

## Outcome

F3.1 reached **functional automated PASS** on `feat/f3-visual-signature` / PR #19 draft. SG PDF Editor can import a transparent PNG signature, place/edit it on the current PDF page, and save a validated copy through PDFium while leaving the original untouched.

## Product behavior added

- `Guardar como...` only; source==destination blocked;

## Architecture

`PdfDocumentSession` stays the read/render UI session. `PdfVisualSignatureWriter` opens the source independently. Native mutation/save is serialized through `PdfiumRuntime.NativeGate`; validation reopens the temporary PDF only after native handles close and the gate is released.

No new NuGet/runtime dependency entered. PDFsharp remains limited to label PDF composition; F3 writer uses PDFium only.

### Ruling during interrupted-session recovery

The approved plan described adding the FIRMAR controls/overlay in XAML. During recovery from an interrupted execution, rewriting the large existing shell was a higher regression risk. The same named controls and behavior are therefore created by the focused `MainWindow.Sign.cs` partial during initialization. This adds no UI framework and keeps reader/ZPL files largely untouched. Cost: some F3.1 UI is imperative instead of declarative.
