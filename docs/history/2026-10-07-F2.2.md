# F2.2 — Labelize Adapter + Preview — Historial

**Fecha:** 2026-10-07  
**Rama:** `feat/f2-2-labelize-preview`  
**PR:** #14 draft, base `feat/f2-1-zpl-parse-open`, sin merge

## Objetivo

Convertir la frontera managed de F2.1 en un preview ZPL real y totalmente local: ejecutar Labelize 1.7.0 como sidecar pinneado, mapear sus PNG a los diseños imprimibles y mostrarlos en WPF con navegación simple, sin multiplicar por `^PQ` y sin dejar datos persistentes del cliente.

## Arquitectura aplicada

```text
ZplDocument.NormalizedRenderSource
  ↓
LabelizeProcessRenderer
  ↓
labelize.exe 1.7.0 convert
  ↓
PNG request-scoped
  ↓ read bytes
ZplRenderedLabel[] managed
  ↓ cleanup
WPF BitmapImage(OnLoad)
```

La integración permanece KISS:

- child process local, no `labelize serve`;
- no HTTP/localhost;
- no wrapper Rust/C ABI;
- no BinaryKits fallback;
- no PDF composition todavía;
- no dependencia runtime comercial ni red en uso normal.

### Task 2 — Child process seguro

`ChildProcessRunner` usa:

- `UseShellExecute=false`;
- `ArgumentList`, sin concatenar shell con input del cliente;
- stdout/stderr redirect;
- timeout acotado;
- cancelación enlazada;
- `Kill(entireProcessTree: true)`;
- drain/cleanup posterior.

### Task 3 — Renderer real + mapping + cleanup

`LabelizeProcessRenderer`:

1. crea temp directory por request;
2. escribe `input.zpl` UTF-8 sin BOM;
3. invoca `labelize.exe convert`;
4. pasa `--format zpl`, `--type png`, `--width`, `--height`, `--dpmm`;
5. resuelve `label.png` o `label_1.png`, `label_2.png`, etc.;
6. ordena outputs numerados;
7. exige count exacto contra diseños imprimibles;
8. lee bytes PNG y valida firma;
9. devuelve `ZplRenderedLabel[]` managed;
10. limpia temporales en `finally`.

Defaults F2.2: 102×152 mm / 8 dpmm. Los controles de tamaño/dpmm pertenecen a F2.3.

Regresiones automáticas cubren:

- single/multi-label;
- `^DF/^XF`;
- Code128 decodificable;
- QR decodificable;
- `^FT + ^BQ`;
- missing runtime;
- cancellation;
- temp cleanup;
- output mapping.

ZXing.Net y SkiaSharp son dependencias solo de test/validación.

### Task 4 — Preview WPF + navegación

Se reemplazó el placeholder textual de F2.1 por preview PNG real.

Estado mínimo agregado en `MainWindow.Labels.cs`:

- documento ZPL activo;
- colección managed de labels renderizadas;
- índice seleccionado;
- CTS del render activo.

Flujo de apertura:

1. cargar/parsear candidate;
2. renderizar candidate con Labelize;
3. si falla, conservar workspace válido anterior;
4. solo si todo pasa, hacer commit del nuevo workspace;
5. mostrar primer PNG;
6. navegar con Previous / `Etiqueta n de N` / Next.

`BitmapImage.CacheOption=OnLoad` garantiza que WPF no mantiene abierto un archivo temporal eliminado. Cada diseño aparece una sola vez; `^PQ` solo informa cantidad total.

Busy state deshabilita Open y navegación. Cerrar la ventana cancela un render activo y el process runner termina el árbol del child process.
