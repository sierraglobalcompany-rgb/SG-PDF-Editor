# History — 2026-10-07 — F2.5 Windows Thermal Print

## Outcome

F2.5 reached **automated PASS** on `feat/f2-5-windows-thermal-print` / PR #17 draft. SG PDF Editor can now prepare and submit exact-size thermal label jobs through normal installed Windows printer drivers, with explicit driver preflight and no silent application scaling.

## Product behavior added

- Windows `PrintDialog` printer selection;
- exact requested thermal `PageMediaSize` from the F2.4 `LabelLayoutPlan`;
- driver capability query + `MergeAndValidatePrintTicket`;
- block if validated media differs by more than 0.5 mm per dimension;
- warn on reported imageable-area clipping without shrinking content;
- request matching printer DPI when exposed;
- normalize Windows `CopyCount` to 1 so SG PDF Editor remains the only quantity authority;
- exact-size `LabelPrintPaginator`, one output label per page;
- no PDF intermediary and no `FitInsidePage` behavior;
- confirmation summary before spool submission;
- `Imprimir etiquetas...` UI only for a valid Thermal layout;
- cancellation/printing preserves the active label workspace and does not rerender Labelize.

## Architecture decisions

F2.5 reuses F2.4 geometry instead of introducing another layout engine. The current thermal `LabelLayoutPlan` is authoritative for page width/height and rotation. The Windows layer validates what the driver accepted; it does not alter the label to make it fit.

`System.Printing` is supplied by the existing Windows Desktop/WPF target. No NuGet dependency was added.
