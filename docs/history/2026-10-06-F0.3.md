## Objetivo

Añadir el zoom mínimo que un lector PDF comercial debe tener, sin inventar UX propia ni adelantar el scheduler/cancelación de F0.4.

## Criterio de producto

Antes de implementar se contrastaron patrones de Adobe Acrobat, Foxit PDF Reader y PDF-XChange Editor. Los tres convergen en una interacción sencilla: controles de zoom, porcentaje visible, tamaño real/100% y ajustes de página/ancho. Foxit además documenta conservar la relación de zoom al cambiar de página.

La implementación adopta ese núcleo y lo simplifica por KISS:

```text
−   100%   +   |   Ajustar página   Ajustar ancho
```

Los presets internos son:

```text
25 / 50 / 75 / 100 / 125 / 150 / 200 / 300 / 400 %
```

Son una selección familiar inspirada en el patrón comercial; no se afirma que sean la lista exacta de ninguno de esos productos.

## Implementado

### Estado de zoom

Nuevo `PdfZoomState` con modos:

```text
Manual
FitPage
FitWidth
```

Reglas:

- 100% equivale a 96 DPI;
- zoom manual usa presets;
- Fit Width calcula DPI desde el ancho útil del viewport y el ancho PDF en puntos;
- Fit Page calcula ancho y alto y usa el factor más restrictivo;
- Fit se limita como máximo a 400%;
- si un Fit deja la página por debajo de 25%, pulsar `−` no puede aumentar la magnificación por accidente;
- `+`/`−` desde un Fit pasan al siguiente preset manual coherente.

### Render

No se estira un bitmap ya rasterizado. Cada cambio de zoom vuelve a llamar a PDFium con el DPI correspondiente.

Esto mantiene calidad en texto/vector durante la rasterización y reutiliza el render ya construido en F0.1.

### WPF

El `BitmapSource` se publica con 96 DPI lógicos aunque PDFium haya rasterizado a otro DPI. Esto es intencional: si WPF publicara el mismo DPI usado para rasterizar, su tamaño lógico compensaría la resolución y el zoom visual tendería a neutralizarse.

Ejemplo conceptual:

```text
100% -> PDFium 96 DPI -> WPF 96 DPI lógico
200% -> PDFium 192 DPI -> WPF 96 DPI lógico -> doble tamaño visible
```

### Navegación

F0.2 se conserva:

- al cambiar de página se mantiene el `PdfZoomState` actual;
- Fit Page/Fit Width se recalculan para las dimensiones de la nueva página;
- el nuevo estado/bitmap se aplica solo tras render exitoso;
- el contexto de sesión/navegación/zoom se valida antes de aceptar el resultado.

### Documento nuevo

Abrir otro PDF reinicia el zoom a 100%. Esto evita heredar de forma sorpresiva un Fit o magnificación extrema de otro documento.

### Resize

No se añadió `SizeChanged` con rerender automático. Si el usuario cambia el tamaño de ventana puede volver a pulsar Fit Page/Fit Width y recalcular inmediatamente.

El auto-refit continuo requiere debounce/cancelación para evitar tormentas de render y por eso queda correctamente en F0.4, junto al scheduler.

1. abrir PDF multipágina;
2. confirmar inicio en 100%;
3. probar `+` y `−` por presets;
4. pulsar porcentaje y volver a 100%;
5. probar Ajustar página;
6. probar Ajustar ancho;
7. navegar y comprobar que conserva el modo/zoom;
8. abrir un segundo PDF y confirmar reset a 100%;
9. redimensionar la ventana y volver a pulsar Fit para comprobar recálculo;
10. confirmar que errores de render no reemplazan la página válida.

Hasta ese smoke, F0.3 está **implementado + automatizado PASS**, no QA visual completo.
