## Scope frozen for V1

F8 adds a separate `COMENTAR` mode with:

- Select;
- Highlight;
- Underline;
- Strikeout;
- Note;
- Ink;
- Rectangle;
- Ellipse.

The exact pinned PDFium runtime was characterized for native `TEXT`, `SQUARE`, `CIRCLE`, `HIGHLIGHT`, `UNDERLINE`, `STRIKEOUT` and `INK` annotations.

Not added in V1: line/arrow/polygon/free-text/stamp creation, attachments/audio, replies/authors/resolved/mentions, cloud collaboration, flatten, pressure-sensitive ink or cross-page selection.

## Architecture actually delivered

- Real PDF annotations; no comment rasterization into page content.
- PDFium remains the only PDF editor engine.
- `CommentWorkspace`/state/history remain managed; native page/annotation handles stay request-scoped.
- `CommentKey(Guid)` is session/workspace identity only.
- Existing-source identity is structural: page + native subtype + SHA-256 structural fingerprint + duplicate ordinal/count.
- `AnnotationIndex` is current-snapshot ordering/descriptor only and is not durable authority.
- Re-resolution fails closed when structure, duplicate cardinality or source identity no longer matches.
- Deterministic hit-testing uses real markup quads, ink segment distance, ellipse/rectangle geometry and `PdfPageDeviceTransform` for rotated-page coordinates.
- `PdfCommentWriter` is separate from edit writer and materializes on a fresh open of the source.
- Save As pipeline is temp sibling → materialize → close handles → reopen/validate → source-race recheck → atomic publish → cleanup.
- Existing unsupported annotations are not reconstructed; they remain preserved/read-only.
- Password-opened and cryptographically signed sources are blocked for comment output.
- No new runtime package, network/cloud/account/API-key/service layer or second PDF editor engine was introduced.
