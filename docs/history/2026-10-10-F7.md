## Scope

F7 adds conservative local editing of real top-level PDF text page objects inside the existing EDITAR mode. It does not add OCR, paragraph reflow, Form XObject text editing, a second PDF engine or a second Save As architecture.

Implemented behavior:

- discover top-level text objects on the active page only;
- preserve exact Unicode plus matrix, bounds/quad, font name, font size, fill and render mode in managed snapshots;
- deterministic hit-testing for text/text and text/image overlaps by topmost page-object index;
- candidate-first text workspace and conservative Rune-based policy;
- read-only handling for unsupported render modes;
- `OriginalFont` edits when the original route is safe;
- pinned DejaVu Sans 2.37 fallback when new code points/size changes require it;
- fallback through PDFium CID Type2 with explicit `ToUnicode` and `CIDToGIDMap`;
- combined image + text materialization, reopen validation and atomic publication;
- Texto V1 UI inside the single EDITAR shell;
- shared dirty guards and one Save As for images + text.

## Architecture retained

- Windows x64, C#/.NET 10, WPF.
- PDFium remains the only PDF editor engine.
- `PdfiumRuntime.NativeGate` remains the global native serialization boundary.
- Persistent text state/workspaces/maps do not store `IntPtr`/`UIntPtr`.
- PDFsharp remains label/synthetic-fixture support, not a general editor engine.
- Labelize remains ZPL-only.
- No new NuGet dependency was added by F7.
- DejaVu Sans 2.37 is committed as an offline runtime asset; provenance, license and hashes are recorded in `third_party/manifest.json`.
- Runtime never downloads the fallback font.
- Source PDF is protected; EDITAR materializes only through Save As.
- Cryptographic signatures and password-opened sources remain blocked.

## Task history

### Task 1 — exact PDFium + Unicode fallback gate

Characterized the pinned PDFium DLL rather than assuming upstream behavior. `FPDFText_LoadFont` routes were rejected after Unicode corruption/normalization evidence. `FPDFText_LoadCidType2Font` with explicit `ToUnicode` + `CIDToGIDMap` successfully reopened exact Unicode and rendered correctly.

### Task 2 — fallback font gate

Pinned unmodified DejaVu Sans 2.37 (`757076` bytes) from the official release. Archive and TTF SHA-256 values plus license notices are recorded in the third-party manifest. Asset loading/copying is offline and adds no PackageReference.

### Tasks 3–4 — shared EDITAR infrastructure/shell

Promoted only the F6 infrastructure that genuinely became shared: fingerprint, preflight, writer/validator naming and the single EDITAR shell/guards. No generic writer hierarchy, DI layer or second edit mode was introduced.

### Task 5 — text discovery

Added active-page-only top-level `FPDF_PAGEOBJ_TEXT` discovery. Unicode, geometry, font/size/fill/render-mode snapshots are fully managed; Form XObject text remains outside F7 V1.

### Task 6 — hit-testing/arbitration

Added quad-based text hit-testing and a small mixed image/text arbiter. Overlaps resolve deterministically to the greatest `PageObjectIndex`; no general geometry engine was introduced.

### Task 7 — conservative policy + workspace

Only Fill text is editable in Texto V1. Invalid/empty content, invalid size and unsupported fallback glyphs are rejected without dirtying state. New non-whitespace runes or size changes choose `FallbackTtf`; safe same-font edits use `OriginalFont`.

### Task 8 — combined writer OriginalFont

Extended the shared writer so image + OriginalFont text edits are resolved before mutation and materialized in one source opening, with `GenerateContent` once per touched page.

### Task 9 — explicit Unicode CID Type2 fallback

Added deterministic rune→CID mapping, explicit `ToUnicode`, big-endian `CIDToGIDMap`, one fallback font plan/load per document and exact save/reopen Unicode evidence. `FPDFText_LoadFont` is not used as product fallback.

### Task 10 — combined output validator

Validator now checks exact Unicode, TEXT type, matrix, size, fill, expected font route and valid render for edited pages, while preserving the existing structural validation and atomic-publication gate.

### Task 11 — independent F7 preservation matrix

F7 re-measured preservation using the real combined image+text writer. Representative fixtures prove preservation of AcroForm/value, bookmarks, named destination/internal link, tagged structure, page labels, attachment payload, metadata and page rotation. See `docs/history/2026-10-10-F7-preservation-matrix.md`.

### Task 12 — Texto V1 UI

Integrated text editing into the one EDITAR surface: mixed selection, conservative properties panel, Apply through the existing policy/workspace, read-only handling, TextBox-local Ctrl+Z, shared dirty guard and combined Save As.

### Task 13 — hardening/regressions

Added focused lifecycle regressions. A real gap was found and fixed: the 2 MiB fallback-font gate is now enforced before both byte reads and `GlyphTypeface` open. Tests also cover active-page-only discovery, no durable native handles, cancel/temp cleanup and dirty-baseline retention on stale/publication failure.
