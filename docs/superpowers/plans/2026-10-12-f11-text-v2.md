# F11 — Texto V2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extender Texto V1 con reconstrucción geométrica determinista de líneas, párrafos y una/dos columnas, permitiendo reflow únicamente cuando la geometría sea clasificada como segura.

**Architecture:** Mantener PDFium como dueño del PDF. Primero introducir un modelo administrado y `TextLayoutAnalyzer` puro, alimentado por la geometría ya extraída en F7; después añadir clasificación/reflow y solo al final integrar la escritura transaccional y la UI existentes. Ninguna dependencia PDF nueva entra sin un gate medible.

**Tech Stack:** C# / .NET 10 / WPF / PDFium / xUnit.

**Spec:** `docs/superpowers/specs/2026-10-12-f11-text-v2-design.md`

## Global Constraints

- Windows x64 / .NET 10 / WPF.
- Offline, gratuito y PDFium-first.
- `Guardar como` para mutaciones; el original no se modifica.
- `NativeGate` conserva la serialización de operaciones PDFium.
- Una o dos columnas simples; layouts arbitrarios no.
- Ambigüedad implica fail-closed.
- PdfPig queda fuera salvo gate comparativo explícito.
- Ningún dato privado real entra al repositorio.
- No merge a `main` sin aprobación explícita.

## Review Focus

1. Objetos fuente fuera de orden: el reading order debe depender de geometría, no de `PageObjectIndex`.
2. Fragmentos vacíos/degenerados/no finitos: deben descartarse sin romper el análisis.
3. Rotación incompatible: debe clasificarse conservadoramente, nunca mezclarse silenciosamente en una línea horizontal.
4. Dos columnas con gutter débil o cruces: debe resultar `Ambiguous`, no una columna inventada.
5. OCR F10: el analyzer debe aceptar geometría válida de texto OCR sin crear una ruta PDF alternativa.
