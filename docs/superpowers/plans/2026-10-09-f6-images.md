# F6 — Edición de imágenes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implementar edición local/offline de objetos de imagen reales en PDF — selección, extracción, reemplazo, transformaciones, undo/redo y Guardar como transaccional — sin raster overlays ni segundo motor PDF.

**Architecture:** `EDITAR` trabaja sobre un `ImageEditWorkspace` lógico y nunca conserva handles nativos como identidad duradera. PDFium descubre objetos y, solo al guardar, reabre la fuente original, resuelve todos los objetos afectados, aplica cambios, regenera páginas tocadas, guarda a temporal, reabre/valida y publica atómicamente. Opacidad y z-order son capability gates del `pdfium.dll` pinneado: si fallan, el núcleo continúa y IMG-03 queda PARTIAL/OPEN.

**Tech Stack:** Windows x64, C#/.NET 10, WPF, `bblanchon.PDFium.Win32 156.0.8076`, PDFsharp 6.2.4 solo para fixtures existentes/sintéticos, xUnit; sin nueva dependencia runtime prevista.

**Spec:** `docs/superpowers/specs/2026-10-09-f6-images-design.md`

## Stop Conditions Requiring Design Review

Return to design instead of improvising if:

1. pinned PDFium lacks a core capability for detect/select/extract/replace/move/resize/rotate/delete;
2. image identity cannot survive selection→Save As without retaining unsafe native handles;
3. common PNG/JPEG replacement requires flattening/raster overlay;
4. transactional writer cannot preserve source/prior destination on failure;
5. credentials would need retention/reuse;
6. core F6 requires second PDF engine;
7. selection overlay requires a large custom rendering framework;
8. preservation requires a generic PDF object-tree rewriter;
9. LEER/FIRMAR/ORGANIZAR/ZPL regression cannot be narrowly isolated.

Opacity or z-order failure alone is not a stop condition for core F6; it is a truthful IMG-03 partial result.
