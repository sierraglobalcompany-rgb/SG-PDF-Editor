# F12.4 Compare UI — Implementation Plan

**Date:** 2026-10-14  
**Design:** `docs/superpowers/specs/2026-10-14-f12-4-compare-ui-design.md`  
**Core owner already closed:** `src/SGPdf.App/Features/Compare/PdfCompareService.cs`

## Goal

Expose the already-closed local Compare core through a minimal WPF flow:

`PDF A already open → Archivo > Comparar con otro PDF... → select PDF B → compare locally → existing right panel summary → close/reset`.

Keep the implementation KISS:
- reuse existing shell and right properties host;
- one focused `MainWindow.Compare.cs`;
- no second viewer/sidebar;
- no ModeManager;
- no new package/PDF engine/backend/cloud;
- no global XAML change unless a failing test proves runtime injection is insufficient.

## Execution rule

From the 2026-10-14 project audit, each user-level `continua` closes **one meaningful bounded task**. RED, GREEN, verification, exact-head CI and KISS/noise audit happen internally before stopping.

Commands used for exact-head verification:

```powershell
dotnet restore SGPdf.slnx --locked-mode
dotnet build SGPdf.slnx --configuration Release --no-restore
dotnet test SGPdf.slnx --configuration Release --no-build
```

## Task 3.1 — Presentation contract + minimal Compare owner

### Files

- Create: `tests/SGPdf.App.Tests/MainWindowCompareTests.cs`
- Create: `src/SGPdf.App/MainWindow.Compare.cs`

### RED

Write the smallest behavior contract for mapping an existing `PdfCompareResult` plus A/B names into presentation text/state.

Required observable semantics:
- A/B file names preserved for display;
- page counts preserved;
- `TextChanged=false` → “Sin cambios”;
- `TextChanged=true` → “Cambios detectados”;
- `VisualChanged` is presented explicitly as **visual change independent of text**;
- structural status derives from page-count equality;
- overall conclusion is “Sin diferencias detectadas” only when counts match and both flags are false;
- otherwise “Se encontraron diferencias”.

The RED must fail because the Compare UI presentation owner does not exist yet, not because the test does not compile.

### GREEN

Implement only the smallest presentation helper/state inside `MainWindow.Compare.cs` or a tiny same-file internal record if needed.

Do **not** add menu, dialogs, panel injection or lifecycle hooks in this task.

### Verification

- run focused Compare UI tests;
- run full exact-head Windows CI;
- audit that only the two planned files changed and no dependency/XAML was added;
- close Task 3.1.

## Task 3.2 — Runtime menu + select B + right-panel results

### Files

- Modify: `src/SGPdf.App/MainWindow.Compare.cs`
- Modify: `tests/SGPdf.App.Tests/MainWindowCompareTests.cs`

### RED

Add behavior covering the usable minimal flow:
- Compare entry point is available only with a PDF A session;
- selecting B is injectable/testable without real dialog automation;
- cancel selection is no-op;
- a selected B calls the existing core with exact A/B paths;
- successful result publishes the presentation to Compare state.

Prefer narrow delegates around file selection/core invocation only if tests demonstrate need. Do not create service interfaces/factories.

### GREEN

In `MainWindow.Compare.cs`:
- inject `Archivo → Comparar con otro PDF...` at runtime;
- inject a Compare panel into the existing right properties host;
- use `OpenFileDialog` for B in production;
- call `PdfCompareService.Compare(_session.FilePath, selectedBPath)`;
- show names/counts/text/visual-only/structure/conclusion;
- add `Cerrar comparación`;
- retain A in the existing viewer/session;
- use existing busy/status conventions.

No `MainWindow.xaml` edit unless runtime injection proves impossible.

### Verification

Focused tests + full exact-head CI + KISS/noise audit.

## Task 3.3 — Lifecycle, guards and controlled errors

### Files

Primary:
- `src/SGPdf.App/MainWindow.Compare.cs`
- `tests/SGPdf.App.Tests/MainWindowCompareTests.cs`

Only if required by failing tests, add focal one-line reset calls to:
- `src/SGPdf.App/MainWindow.Reader.cs`
- `src/SGPdf.App/MainWindow.Forms.cs`
- `src/SGPdf.App/MainWindow.Sign.cs`
- `src/SGPdf.App/MainWindow.Edit.cs`
- `src/SGPdf.App/MainWindow.Organize.cs`

### RED

Cover:
- opening/changing document resets Compare;
- entering an incompatible tool resets Compare;
- existing dirty Edit/Organize/Sign guards are honored before starting Compare;
- invalid/unreadable/protected B produces a controlled error;
- an error never replaces/destroys A;
- `Cerrar comparación` clears B/result and restores normal properties placeholder where appropriate.

### GREEN

Add only the lifecycle/reset/error logic demanded by those tests.

`ResetCompareUi()` remains focal. Do not create a global mode coordinator/state machine.

Password-protected B stays outside the first Compare scope: report controlled failure rather than add credential architecture.

### Verification

Focused tests + complete exact-head CI + regression attention to Reader, Sign, Forms, Edit and Organize.
