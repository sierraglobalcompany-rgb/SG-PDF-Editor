# F12.1 Safe Redaction — Implementation Plan

> Execute in small TDD slices. Do not merge to `main`. Do not add another PDF engine or a second general writer.

**Goal:** Implement real, fail-closed redaction of complete simple PDF text objects by removing the underlying objects and adding opaque black rectangles, with transactional Save As and reopened-output validation.

**Architecture:** Reuse PDFium, `PdfTextObjectInfo`, existing EDITAR preflight/fingerprint and the existing transactional writer path. Add only the redaction-specific pure policy/plan/workspace needed to feed that path. WPF comes last.

**Tech stack:** C# / .NET 10 / WPF / pinned PDFium (`bblanchon.PDFium.Win32` 156.0.8076) / xUnit / Windows CI.

## Task 2 — Pure fail-closed policy and immutable plan

**Files**
- Create: `src/SGPdf.App/Features/Edit/Redaction/RedactionPlan.cs`
- Create: `src/SGPdf.App/Features/Edit/Redaction/RedactionPolicy.cs`
- Create: `tests/SGPdf.App.Tests/RedactionPolicyTests.cs`

**RED corpus**
- simple visible horizontal whole text object => allow;
- multiple compatible whole objects => allow;
- render mode invisible/OCR => reject;
- rotated/skewed transform => reject;
- invalid/degenerate bounds => reject;
- unsafe overlap => reject;
- blocked preflight => reject;
- empty selection => reject;
- duplicate object keys => reject;
- objects spanning invalid/mismatched pages as applicable => reject.

**GREEN**
1. Model immutable redaction target(s) from existing `PdfTextObjectInfo` snapshots.
2. Return a small decision result with conservative Spanish reason on rejection.
3. Do not perform I/O, PDFium mutation, WPF or dependency changes.
4. Reuse existing geometry/model types instead of duplicating F11.
5. Exact-head CI must pass before Task 3.

## Task 3 — Redaction workspace and transactional materialization

**Files**
- Create narrowly scoped redaction workspace under `Features/Edit/Redaction` if required by transaction identity/dirty state.
- Modify: `src/SGPdf.App/Pdf/PdfEditWriter.cs`
- Add a small redaction output validator or extend the existing validator only if that keeps responsibilities clearer and smaller.
- Add focused integration tests under `tests/SGPdf.App.Tests`.

**RED requirements**
1. Safe plan can be staged without mutating source.
2. Save As removes the exact underlying text object(s).
3. Reopened PDF text extraction/search no longer finds redacted text.
4. Neighboring text survives.
5. Opaque black rectangle is present in the expected region.
6. Reopened page renders successfully.
7. Source bytes are unchanged.
8. Signed PDF remains blocked.
9. Unknown/changed object snapshot rejects before first mutation.
10. Cancellation/failure leaves no partial published destination and cleans temporary output.

**GREEN implementation constraints**
1. Reuse the existing EDITAR transaction; no second general writer.
2. Resolve and validate every target handle before first mutation.
3. Remove approved text objects, destroy their handles safely, create opaque black rectangles, insert deterministically, generate page content once.
4. Preserve existing image/text edit behavior and workspace identity checks.
5. Validate the temporary output before atomic publication.
6. Exact-head Release build + suite + Windows CI.
