# F5 Organizar PDF Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement `ORGANIZAR` as a safe, offline, plan-first workspace for reorder/rotate/delete/duplicate/insert/merge/extract/split, with conservative structural preflight and transactional `Guardar como...` output.

**Architecture:** PDFium remains the only PDF engine. UI actions mutate an in-memory `OrganizePlan`; native PDF materialization happens only when output is requested. `ORGANIZAR` has a dedicated virtualized thumbnail surface separate from F4 `LEER`, F3 `FIRMAR` and ZPL. Outputs are created in a temporary PDF by exact page imports + planned rotations, then closed, reopened, validated and atomically published. Cryptographically signed PDFs and password-required PDFs are blocked from F5 structural output/import in the initial version.

**Tech Stack:** C# / .NET 10 / WPF / PDFium `bblanchon.PDFium.Win32` 156.0.8076 / existing PDFsharp 6.2.4 for deterministic synthetic fixtures / xUnit. No new runtime package.

**Spec:** `docs/superpowers/specs/2026-10-09-f5-organize-design.md`

**Exact base:** F4 closure `1d620f1b2b9717aab35671e18a9dc78f28a8afdd`.

## Global Constraints

- Windows x64 + C#/.NET 10 + WPF.
- PDFium remains the only PDF engine unless a later demonstrated gap is separately approved.
- All PDFium calls use the same `PdfiumRuntime.NativeGate` semaphore via `Wait`/`Release`; no `lock(NativeGate)` path may remain.
- No cloud, HTTP service, account, API key, telemetry, database, WebView2 or runtime network dependency.
- No new runtime NuGet package for F5.
- Initial F5 is `Guardar como...` only; never overwrite the active source PDF.
- Never publish output before temp save + native close + reopen + validation succeeds.
- Runtime validation renders every output page sequentially at 36 DPI, one bitmap at a time.
- Cryptographic signature count > 0 = Block.
- A source that required a password to open = Block for structural output/import.
- `UNKNOWN` preservation is never presented as preserved.
- Plan/state logic stays independent from WPF; native writer stays independent from tile controls.
- Raw PDFium document handles are not exposed broadly.
- F4 LEER, F3 FIRMAR and F2 ZPL remain regression gates.
- Earlier manual/private/physical QA stays NOT RUN unless actually executed.
- No merge to `main` without explicit user approval.
- Execute one task at a time. At F5.1/F5.2/F5.3/F5.4/F5.5 checkpoints, push and require exact-head Windows CI PASS before continuing.

## Review Focus

1. **Non-contiguous multi-selection moved forward/backward** preserves relative order with no duplicate/lost IDs. Test: `MoveSelection_NonContiguousForwardBackward_PreservesRelativeOrderWithoutLoss` (Task 2).
2. **Secondary source disappears/changes after being added** fails before publication and preserves existing destination. Test: `SaveAsCopy_SourceChangedOrMissingBeforeMaterialization_PreservesDestination` (Task 4/7).
3. **Very large organize workspace** never eagerly renders all thumbnails. Test: `LargeDocument_OnlyRealizedPlusNeighborThumbnailsHoldBitmaps` (Task 5).
4. **Split output collision** blocks before first bulk write; no silent overwrite. Test: `SplitPublish_AnyExistingTarget_BlocksBeforeFirstWrite` (Task 8).
5. **Noncrypto structures not proven preserved** require explicit warning; signed/password sources always block. Test: `Preflight_UnknownOrChangedNonCryptoStructure_RequiresExplicitWarning` (Task 9).

## Task 4 — F5.2 Transactional Writer + Output Validator

**Files**

- Create: `Pdf/PdfOrganizeWriter.cs`, `Pdf/OrganizeOutputValidator.cs`
- Modify: `Pdf/PdfDocumentSession.Organize.cs`
- Create tests: `PdfOrganizeWriterTests.cs`, `OrganizeOutputValidatorTests.cs`

**Output expectation contract**

```csharp
internal readonly record struct OrganizeExpectedPage(
    PdfPageSize PageSize,
    int RotationQuarterTurns);

internal sealed class OrganizeOutputValidator
{
    internal void Validate(
        string outputPath,
        IReadOnlyList<OrganizeExpectedPage> expectedPages,
        CancellationToken cancellationToken = default);
}

internal sealed class PdfOrganizeWriter
{
    internal void SaveAsCopy(
        OrganizePlan plan,
        string activeSourcePath,
        string destinationPath,
        bool warningsConfirmed,
        CancellationToken cancellationToken = default);
}
```

The writer computes **absolute expected output rotations and page sizes while source documents are open** and passes those descriptors to the validator. Validator does not reopen source PDFs or attempt to infer absolute rotation from a delta-only plan.

`warningsConfirmed=false` is the defense-in-depth default. Writer re-preflights source files before temp creation: Block always throws; Warning throws unless `warningsConfirmed=true`.

- [ ] **Step 1: RED validator tests.**

Exact count/sizes/rotations pass; wrong count/size/rotation fails; every page renders at 36 DPI sequentially; cancellation aborts.

- [ ] **Step 2: RED writer tests.**

Exact marker reorder; duplicate page; subset delete; mixed original+delta rotation; source==active destination rejected; destination replaced only after validation; native/validation failures preserve destination + clean temp; `SaveAsCopy_SourceChangedOrMissingBeforeMaterialization_PreservesDestination`; signed/password/preflight Block never creates temp; Warning needs `warningsConfirmed=true`.

- [ ] **Step 3: Implement minimum materializer.**

1. validate plan/destination;
2. require all fingerprints match;
3. before temp creation, open each source unprotected through `PdfDocumentSession` and run preflight; protected load error becomes controlled F5 block; signed = Block; Warning requires authorization;
4. open required native source handles with password null;
5. create destination;
6. import one logical page at a time using `FPDF_ImportPagesByIndex`;
7. capture source page size/current rotation, apply `(current + delta) & 3` on imported page, append corresponding `OrganizeExpectedPage`;
8. save request-scoped temp;
9. close native handles/release semaphore;
10. reopen/validate temp from expected descriptors;
11. atomic replace/move destination;
12. temp cleanup in `finally`.

Never invoke a public `PdfDocumentSession` method while already holding `NativeGate`.

- [ ] **Step 4: Implement validator GREEN.**

Reopen through `PdfDocumentSession`; verify expected count, finite positive page sizes with small numeric tolerance, absolute rotation for every page and render every page at exactly 36 DPI one-at-a-time. Unique text-marker order remains an integration-test assertion, not runtime OCR/text indexing.
