# F10 Local OCR Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn scanned/image-only PDF pages into locally OCR'd, searchable/selectable/copyable pages while preserving the original visual page, document structures, source file, and SG PDF Editor's offline Save As guarantees.

**Architecture:** PDFium remains the PDF owner: it detects existing text, renders OCR candidates, maps device coordinates back to PDF space, writes the searchable layer if the exact pinned runtime proves true invisible text support, and validates the saved output. Tesseract is a private Windows x64 sidecar used only for recognition and TSV geometry; F10 never uses Tesseract-generated PDF as the final document.

**Tech Stack:** C# / .NET 10 / WPF / pinned `bblanchon.PDFium.Win32 156.0.8076` / existing DejaVu Sans 2.37 CID Type2 path / Tesseract local sidecar selected only after provenance+license+offline gate / `tessdata_fast` `spa` + `eng` after digest verification.

**Spec:** `docs/superpowers/specs/2026-10-11-f10-local-ocr-design.md`

## Global Constraints

- Branch: `feat/f10-local-ocr`, stacked exactly from F9 automated closure `222454f5782f84a929c7fd610c284d15df8f869d`.
- Keep `main` frozen; no merge without explicit user approval.
- Offline by construction: no OCR cloud, API keys, accounts, telemetry dependency, system-PATH dependency, or runtime download.
- One OCR engine only: Tesseract. No hidden fallback engine.
- PDFium remains primary PDF engine; do not add another PDF writer unless Task 1 produces an executable NO-GO.
- Preserve the original page; never replace a valid page with a Tesseract-generated raster PDF page.
- Save As only: source untouched, sibling/request temp artifacts, reopen validation, source-race recheck, atomic publication, cleanup on all paths.
- Automatic mode OCRs only pages without meaningful existing text; current-page/range scope uses the same eligibility policy and does not force duplicate OCR text.
- Language UX is fixed: Español default, Inglés, Español + Inglés. Internal mappings are `spa`, `eng`, `spa+eng`.
- Initial OCR raster target is 300 DPI, page-at-a-time, sequential by default.
- Signed PDFs are blocked. Password-opened/encrypted PDFs are blocked for F10 V1 unless a later explicit preservation gate is separately approved.
- TDD per task: observable RED → minimum GREEN → targeted tests → full suite/exact-head Windows CI → checkpoint.
- Manual Windows/Adobe/Foxit/Edge/private-corpus QA remains **NOT RUN** unless actually executed.
- No task may mark Tesseract `runtime-current-f10` until exact Windows distribution provenance, digest, licenses/notices, `spa`/`eng` digests, and offline execution are green.

## File Structure

- `src/SGPdf.App/Features/Ocr/` owns OCR-only managed models, page eligibility, Tesseract process integration, TSV parsing, coordinate mapping, orchestration, and dialog UI.
- `src/SGPdf.App/Pdf/PdfiumNative.Ocr.cs` owns only OCR-specific PDFium interop/constants proven by Task 1.
- `src/SGPdf.App/Pdf/PdfOcrWriter.cs` owns searchable-layer persistence; it reuses F7 font primitives and F9 transaction patterns without turning `PdfTextOverlayWriter` into a generic mega-writer.
- `src/SGPdf.App/Pdf/PdfOcrOutputValidator.cs` owns semantic reopen/search/render validation for OCR output.
- `src/SGPdf.App/MainWindow.Ocr.cs` is a thin WPF adapter; `MainWindow.xaml` gets only command/menu wiring.
- `tools/setup-tesseract.ps1`, `third_party/manifest.json`, `third_party/licenses/`, the app project file, and Windows CI own dependency staging only after Task 2 GO.
- `tests/SGPdf.App.Tests/` contains synthetic deterministic OCR fixtures/harnesses; private real PDFs stay outside Git.

## Review Focus

1. **Sparse pre-existing text over a scanned page** — a page number/header must not automatically prevent OCR, while a genuinely searchable page must not receive a duplicate hidden layer. Task 3 pins the deterministic eligibility threshold and boundary tests.
2. **Rotated/landscape/cropped pages** — TSV pixel rectangles must map to correct PDF coordinates and remain selectable around the recognized text. Tasks 1 and 4 own tests.
3. **Malformed/hostile OCR output** — bad TSV columns, negative dimensions, non-finite/confidence values, invalid UTF-8/process errors must fail the transaction rather than publish partial OCR. Tasks 3, 4 and 6 own tests.
4. **Cancellation/timeout after destination already exists** — the old destination must survive byte-for-byte and all request-scoped temps/processes must be cleaned. Tasks 3, 5 and 6 own tests.
5. **Large/high-DPI or unusual page sizes** — 300-DPI raster sizing must reject overflow/unreasonable allocation deterministically instead of exhausting memory. Task 4 owns the bounded-raster test.

- `OcrCoordinateMapper.Map(PdfRenderedPage renderedPage, OcrPixelRect bounds) -> PdfOcrRect` uses `PdfRenderedPage.DeviceTransform`; it maps all four rectangle corners so 0/90/180/270 rotations are handled by the existing PDFium-derived transform rather than hand-coded orientation guesses.
