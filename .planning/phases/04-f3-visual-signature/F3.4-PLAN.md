## Product contract delivered

F3.4 persists and reloads the existing `SignatureAsset` locally. It does not persist PDF placement geometry and does not create a second signature/PDF pipeline.

```text
existing SignatureAsset
  ↓ save
%LOCALAPPDATA%\SG PDF Editor\Signatures\
  library.json + <guid>.png
  ↓ load
existing SignatureAsset
  ↓ Use
existing AddSignatureAsset(...)
```

## Delivered behavior

- local/offline-only library; no cloud/account/database/encryption claim;
- manifest v1 is authoritative and corruption is preserved, not auto-repaired;
- GUID-based physical PNG names for newly added items; display names remain metadata only;
- duplicate display names rejected case-insensitively after trim on add/rename;
- lossless transparent PNG through WPF encoder and existing 20M-pixel loader guard on reload;
- same-directory temp/publication ordering for Add/Rename/Delete;
- Add publishes PNG before manifest reference; failed manifest publication rolls back only the current PNG best-effort;
- Delete publishes logical removal before best-effort PNG cleanup;
- missing/corrupt PNG affects only its row; orphan PNG is ignored;
- library dialog supports Use, Save selected, Rename, Delete and Close with thumbnail/name/status;
- Save selected stores the exact selected placement's `SignatureAsset` without changing PDF state;
- successful Use returns an asset and invokes existing `AddSignatureAsset(...)` exactly once;
- cancel/failure preserves placements, selection and dirty state;
- no new package, PDF writer/coordinate change, ZPL change or MainWindow framework refactor.
