# F0.2 Page Navigation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add bounded previous/next page navigation to the PDF opened by F0.1, with a visible current-page counter and no out-of-range navigation.

**Architecture:** Keep PDF rendering in the existing `PdfDocumentSession` and keep WPF as a thin orchestrator. Introduce one small immutable navigation-state class so page bounds can be tested without UI automation; render the candidate page in the background and commit the new navigation state only after render succeeds.

**Tech Stack:** WPF, .NET 10, C#, PDFium, xUnit, GitHub Actions Windows runner.

**Spec:** `.planning/phases/01-f0-pdf-base/PLAN.md` — F0.2 is the navigation-only follow-up to F0.1.

## Global Constraints

- Windows desktop, WPF + .NET 10.
- Offline-only; no network dependency.
- PDFium remains the PDF engine and native calls remain globally serialized.
- No zoom/fit in this slice; that is F0.3.
- No scheduler/cancellation/progressive rendering; that is F0.4.
- No print/ZPL/sign/edit/OCR work.
- No merge to `main` without explicit user approval.

## Review Focus

- A one-page PDF must disable both navigation directions.
- The first page must never navigate below index `0`.
- The last page must never navigate beyond `PageCount - 1`.
- A failed render must leave the currently displayed page/state unchanged.
- A stale render from an older session must not overwrite a newly opened document.
