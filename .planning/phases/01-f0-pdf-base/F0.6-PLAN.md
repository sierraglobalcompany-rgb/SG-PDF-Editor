# F0.6 — QA / Hardening / Offline

## Objetivo

Cerrar técnicamente la implementación automatizada de F0 PDF Base antes de Gate ZPL-A, corrigiendo solo huecos demostrados por auditoría de requisitos y añadiendo verificaciones de regresión/offline.

## Requisitos de cierre

- `PDF-BASE-01`: abrir PDF local.
- `PDF-BASE-02`: render PDFium fuera del UI thread.
- `PDF-BASE-03`: anterior / siguiente / **ir a página**.
- `PDF-BASE-04`: zoom + fit page + fit width.
- `PDF-BASE-05`: cancelar renders obsoletos/priorizar visible.
- `PDF-BASE-06`: impresión Windows.
- `PDF-BASE-07`: funciones principales sin red.

## Hallazgo de auditoría

F0.2 implementó anterior/siguiente, pero no una acción de **ir a página**. F0.6 cerró el hueco con el patrón comercial KISS `Página [n] de N`, sin crear otro pipeline de render.

## Implementación

### Go to page

- `PageNavigationState.GoToPageNumber(int)` usa numeración visible 1-based.
- Rango estricto `1..PageCount`.
- Misma página devuelve el mismo estado.
- El TextBox usa Enter para navegar y reutiliza `NavigateAsync`.
- Esc, pérdida de foco o entrada inválida restauran el número vigente sin modificar estado.

### Offline guard

`OfflineRuntimeTests` protege:

- ausencia de referencias directas a ensamblados de red;
- ausencia de clientes/endpoints de red en código runtime;
- ausencia de navegación remota en XAML;
- superficie NuGet runtime exacta: solo `bblanchon.PDFium.Win32`.

El guard no confunde URIs de namespace WPF con acceso de red.

### Hardening PDF

Fixtures sintéticos locales cubren:

- PDF de una página;
- PDF real de 3 páginas;
- PageCount y render de la última página;
- límite de página fuera de rango;
- archivo inválido con error controlado.

No se versionan datos privados ni se requiere red.
