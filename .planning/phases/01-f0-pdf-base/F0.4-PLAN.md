# F0.4 — Scheduler + Cancel

## Objetivo

Evitar que renders obsoletos de ajuste compitan por PDFium o publiquen resultados viejos, manteniendo una solución pequeña y compatible con el flujo existente.

## Alcance

- scheduler latest-request-wins para rerenders automáticos;
- cancelación cooperativa mediante `CancellationToken`;
- espera del mutex global PDFium cancelable;
- rechazo de trabajo/resultados cancelados antes de publicación;
- auto-refit al redimensionar en `FitPage` y `FitWidth`;
- debounce corto de resize;
- prioridad de acciones manuales sobre auto-refit;
- tests unitarios/integración y Windows CI.

## Diseño KISS

### Scheduler

`PdfRenderScheduler` mantiene una sola solicitud vigente. `Begin()` cancela la anterior y entrega una versión/token nuevos. `IsCurrent()` permite comprobar que solo la última solicitud publique resultado.

No se implementan:

- cola general;
- workers persistentes;
- prioridades múltiples;
- CQRS/event bus;
- scheduler por documento/página.

### Cancelación PDFium

Los overloads existentes de `GetPageSize` y `RenderPage` se conservan. Se añaden variantes con `CancellationToken`.

La cancelación se comprueba:

1. antes de validar/cargar trabajo;
2. al esperar `PdfiumRuntime.NativeGate`;
3. antes de `FPDF_RenderPageBitmap`;
4. después de la llamada síncrona;
5. antes de devolver/publicar el raster.

`FPDF_RenderPageBitmap` no se intenta interrumpir a mitad de llamada. Hacerlo correctamente exige progressive rendering y más estado nativo. Se difiere salvo evidencia real de latencia que lo justifique.

### Resize + Fit

- Solo aplica si el modo actual es `FitPage` o `FitWidth`.
- `SizeChanged` inicia una solicitud latest-request-wins.
- Debounce: 150 ms.
- El viewport se lee después del debounce, no antes.
- Apertura, navegación y zoom manual cancelan cualquier resize pendiente.
- La UI no bloquea toda la ventana durante resize automático.
- Antes de publicar se revalidan scheduler, sesión, navegación y zoom.

## Criterios de aceptación automatizados

- [x] una solicitud nueva cancela la anterior;
- [x] solo la solicitud más nueva es current;
- [x] `CancelCurrent()` invalida la solicitud activa;
- [x] dispose cancela la solicitud activa;
- [x] PDFium acepta tokens sin romper overloads anteriores;
- [x] un token pre-cancelado evita entrar al render;
- [x] build Release PASS;

- [x] resize-fit compila integrado en WPF.

## QA físico pendiente

En Windows interactivo:

1. abrir un PDF real;
2. activar Fit Page y redimensionar rápido varias veces;
3. confirmar que termina ajustado al último tamaño;
4. repetir con Fit Width;
5. durante resize, ejecutar una navegación o zoom manual y confirmar que la acción explícita prevalece;
6. confirmar que en zoom Manual el resize no dispara auto-refit;
7. repetir con PDF pesado para observar si la llamada nativa síncrona introduce latencia visible.

## Fuera de alcance

- progressive rendering;
- abortar una llamada nativa ya iniciada;
- impresión;
- thumbnails/search;
- ZPL/firma/edición/OCR.
