## Goal

Add simple output-quantity controls and physical label render settings on top of the stable F2.2 Labelize preview, without starting layout/PDF composition or thermal printing.

## Scope delivered

- quantity mode `Del archivo` using each printable design's parsed `^PQ`;
- quantity mode `Una de cada` = one copy per printable design;
- custom quantity per design, 1–99,999,999;
- quantity changes update output totals without rerendering Labelize;
- right-side WPF properties panel shown only for ZPL workspace;
- label size presets: 102×152 mm, 100×150 mm, 100×100 mm;
- custom width/height in millimeters applied explicitly by button;
- 6 / 8 / 12 / 24 dpmm choices;
- size/dpmm changes rerender the original normalized ZPL with Labelize rather than stretching the previous bitmap;
- selected printable design is preserved after successful rerender;
- failed/cancelled rerender preserves last valid PNG preview and applied render settings;
- opening another ZPL uses the current physical render settings while resetting quantity mode to `Del archivo`.

## Out of scope

- A4/Carta;
- 1/2/3/4/6/8/10/12/custom multi-up layout;
- PDF composition/export;
- PDFsharp dependency;
- thermal printing;
- printer capability discovery;
- private Mercado Libre fixtures in Git;
- physical printer/scanner acceptance.

## KISS implementation

No ViewModel framework, DI container, generic render abstraction, new project or new NuGet dependency was added. A small delegate seam in `MainWindow.Labels.cs` keeps the existing Labelize renderer directly testable while production still calls `LabelizeProcessRenderer`.

Quantity is output metadata only:

```text
ZplDocument.Designs + QuantityFromFile
          ↓
ZplQuantitySelection
          ↓
output total / later composition
```

Physical render settings remain separate:

```text
width mm + height mm + dpmm
          ↓
ZplRenderOptions
          ↓
LabelizeProcessRenderer
          ↓
new managed PNG previews
```
