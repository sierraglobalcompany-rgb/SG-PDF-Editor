**Date:** 2026-10-07

## Goal

Add the first production ZPL slice without yet invoking Labelize: open local `.zpl/.txt/.prn`, parse printable ZPL designs, preserve `^PQ` as quantity metadata, retain document-level stored-format context, and safely switch the WPF workspace only after a valid parse.

## Scope delivered

- immutable `ZplDocument` / `ZplDesign` model;
- pure managed `ZplDocumentParser`;
- complete `^XA...^XZ` block validation;
- `^DF` support blocks excluded from user-visible designs while source order remains in the document render stream;
- `^XF` invocation context preserved;
- `^PQ` extracted as metadata and removed from `NormalizedRenderSource`;
- strict local UTF-8 loader for `.zpl/.txt/.prn`;
- WPF `Archivo > Abrir etiquetas ZPL...`;
- safe PDF ↔ ZPL workspace replacement;
- no Labelize process/runtime package yet.

## Out of scope

- Labelize sidecar invocation;
- PNG preview;
- quantity-selection UX;
- thermal dimensions/layout/PDF export/printing;
- private Mercado Libre fixtures in Git;
- physical printer/scanner validation.

## Accepted semantics

- absent `^PQ` => quantity 1;
- `^PQ0` => quantity 1;
- multiple `^PQ` in one printable block => last quantity wins;
- every `^PQ` is removed from render input;
- quantity maximum: 99,999,999;
- malformed/out-of-range `^PQ` => controlled `InvalidDataException`;
- `^PQ` inside a `^DF` stored-format definition is rejected in F2.1 rather than silently guessed;
- `TotalQuantityFromFile` is `long`;
- invalid ZPL never replaces the current valid document state.

## Implementation notes

- label UI integration lives in `MainWindow.Labels.cs`, a partial of the existing window, to avoid inflating the existing `MainWindow.xaml.cs`; no ViewModel/service/framework was introduced.
- `OpenZplMenuItem.IsEnabled` follows the existing PDF Open busy state, so there is no second busy-state mechanism.
- successful ZPL commit disposes the prior PDF only after parsing succeeds.
- successful PDF rendering clears the prior ZPL workspace reference when the PDF becomes visible.
- private/customer ZPL is not versioned and is not required for automated CI.
