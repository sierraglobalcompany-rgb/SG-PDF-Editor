# F2.2 — Labelize Adapter + Preview

**Date:** 2026-10-07

## Goal

Connect the managed F2.1 ZPL model to pinned Labelize 1.7.0 through a local child process and show one navigable WPF PNG preview per printable design, while keeping customer data local and temporary.

## Scope delivered

- pinned Labelize 1.7.0 Windows x64 staging for development/CI;
- SHA-256 verification of the release archive;
- local runtime resolver for bundled `labelize/labelize.exe`;
- safe child-process runner with stdout/stderr, timeout, cancellation and process-tree kill;
- `LabelizeProcessRenderer` using request-scoped temporary directories;
- explicit width/height/dpmm render options;
- deterministic single/multi-output PNG mapping;
- exact output-count validation against printable ZPL designs;
- managed PNG bytes loaded before temp cleanup;
- Code128, QR, `^FT + ^BQ` and `^DF/^XF` regressions against real Labelize in Windows CI;
- WPF PNG preview with Previous / `Etiqueta n de N` / Next navigation;
- candidate-first parse + render before replacing the current valid workspace;
- closing the window cancels an active Labelize render;
- `^PQ` remains quantity metadata and never multiplies preview renders.

## Out of scope

- quantity-selection UX;
- custom quantity;
- final physical-dimension controls;
- A4/Carta or multi-up composition;
- PDF export/composition;
- thermal printing;
- printer capabilities;
- BinaryKits runtime fallback;
- local HTTP/server architecture;
- private Mercado Libre fixtures in Git;
- physical printer/scanner acceptance.

## Architecture kept KISS

```text
ZplFileLoader
  ↓
ZplDocumentParser
  ↓
ZplDocument.NormalizedRenderSource
  ↓
LabelizeProcessRenderer
  ↓ local child process
labelize.exe 1.7.0 convert
  ↓
request-scoped PNG files
  ↓ read all bytes
managed ZplRenderedLabel[]
  ↓ cleanup temp
WPF BitmapImage(OnLoad)
```

No ViewModel framework, server, custom Rust ABI, dual renderer abstraction or new production NuGet package was introduced for the preview UI.
